# 杏规：语料、使用与评测

## 1. 语料来源与版本

本地 `docs` 中两份 PDF 都有可提取的文本层，解析测试会在构建时校验。

| 文件 | 用途 | 问答状态 | 依据 |
|---|---|---|---|
| `2026年全日制学术学位硕士研究生培养方案_261716157506.pdf` | 2026 级全日制学术硕士培养要求 | 有效，按 2026 级适用 | [电子科技大学研究生院培养方案页面](https://gr.uestc.edu.cn/tongzhi/119/7725)及其附件 |
| `20190412092930_47083.pdf` | 研究生学位授予实施细则历史文本 | 已过期，不进问答 | [学校信息公开网列有后续修订](https://xxgkw.uestc.edu.cn/xxgkml/xw_xkxx/sybs_ss_xsxwdjbyq.htm) |

`corpus-manifest.json` 记录文件哈希、来源、发布部门、身份和学年。执行 `POST /api/corpus/bootstrap` 时先核验全部文件哈希，再导入；重复文件名跳过。研究生院页面为多年更新的列表页，网页的“2019-05-05”是列表页原始发布时间，不能冒充 2026 版附件的发布日期。因此清单中 `publishedAt` 与 `effectiveFrom` 留空，以 `academicYear=2026` 限定适用范围。

旧文本的具体废止条款与日期尚未从校方原文核实，系统以 `expired` 停止其问答用途。使用时应继续查证 2026 修订文件并补入新版全文。

## 2. 数据流

```text
PDF/文本 → 提取与清洗 → 保存原始文件和规则元数据 → 按条款或专业章节切片
  → 异步生成向量与关键词索引 → 仅放行有效、已索引、适用日期内的规则
  → 当前有效规则过滤 → 向量 + 关键词检索 → RRF + 证据闸门
  → 附规则来源、版本和适用范围生成回答 → 可回看原文
```

原有技术笔记在表结构迁移后状态为 `draft`，不会进入杏规问答。规则正文更新会置 `index_ready=false`；异步重建成功后再恢复。导入的原 PDF 存在数据库 `note.original_file` 中。已保存的历史答案保留当次引用的规则元数据快照，但规则现状仍需重新查询。

当前版本采用公开规则库模式。`audience`、`campus`、`academic_year` 是规则适用范围元数据，会随引用展示；它们暂不作为用户登录权限，也不会因为提问未填写身份、校区或学年而阻断检索。统一身份认证、用户角色解析、规则库授权和按权限过滤列入后续 TODO。

## 3. 评测口径

评测集 `src/test/resources/eval/campus_eval_v1.jsonl` 和扩展集 `src/test/resources/eval/campus_eval_v2.jsonl` 都使用真实培养方案中的片段标注，不固定 `noteId:seq`。运行时通过文件名、专业上下文和原文短句定位期望切片；定位失败则跳过并报出样本，不给虚假成绩。`CampusEvalCorpusTest` 无需数据库或模型，可验证金标准片段确实存在于 PDF 清洗后的切片中。v1 是 15 条快速回归集；v2 是 40 条扩展验收集，含 30 条应答、5 条无依据应拒答、5 条适用范围近邻。后者检查回答有没有把邻近版本或其他身份的规则冒充为问题所问规则，不纳入过召回率分母。

| 指标 | 含义 | 现状 |
|---|---|---|
| Hit@5、Recall@5、MRR | 必要证据是否进入前五位 | 可运行，需 DB 与 Embedding |
| 误拒率、过召回率 | 应答题是否无证据、无依据题是否误放 | 可运行，应拒答样本只有 3 条，置信度很低 |
| 来源日期有效率 | 返回的资料日期范围覆盖评测日 | 可运行，无法代替审核真实版本 |
| 来源适用范围匹配率 | 来源的身份、学年与样本标注一致 | 可运行，未标注场景不计入分母 |
| 角标可映射率 | `[n]` 可映射到一个 sources 元素 | 可运行，**不等于引用支撑率** |
| 必要事实字面覆盖率 | 人工金标准中的必要事实或其预设措辞是否出现在答案 | 可运行，基于字符串归一化，会漏掉未预设的同义表达；不能当作语义正确率 |
| 禁止事实零命中率 | 答案是否避开人工标注的错误或不允许结论 | 可运行，命中后需人工确认语义 |
| TTFT P50/P95 | 请求到首个模型 token 的耗时 | 可运行，需真实模型 |
| Judge 答案评分 | 必要事实、禁止事实、引用和适用范围综合评分 | 可运行，需独立 Judge 模型；必须人工抽检 |

运行命令见根目录 README。真正评价“规则是否答对”还应对每个样本人工标注事实完整性、每个结论的引用支撑、版本冲突和澄清行为。目标继续扩展到至少 100 条校园问题，覆盖本科/研究生、不同校区与学年、时效性、例外、冲突、部分可答、无答案。当前 v2 已适合做第二轮验收，但仍不能代表完整校园规则库。

每次增加或修订文档后，先审核官网链接和适用范围，重新生成索引，再跑 `CampusEvalCorpusTest`、检索评测、生成评测；只把语料指纹和评测集 SHA-256 均相同的基线与新运行对比。更换语料、评测题、分块策略或模型时，不能直接比较旧分数。

## 4. 上线前事项

`ChunkQualityEvalTest` 会直接在真实 PDF 上检查金标准事实与必要专业上下文是否落在同一 chunk，并报告平均长度和过短块比例。当前首批语料的金标准事实同块率和上下文保留率均为 100%，这只是少量证据标注的结果，不能代表所有规则。

当前服务只监听本机。面向学生开放前应加入管理员登录、规则发布审核、上传者记录、来源定期核验与备份。尤其需要取得最新版学位授予细则，并针对培养方案中的课程表增加表格结构解析或人工校对。机器生成答案始终提供官网原文链接，不能作为学校审批结论。
