## 仍然存在的问题

1. 无依据题仍然被检索闸门放行，3/3 题进入了 DeepSeek。虽然 DeepSeek 最终正确拒答，但这会增加延迟和成本，也会给生成模型提供不必要的上下文。
2. 当前语料元数据仍需修正。回答中展示的发布部门、来源首页、适用对象和日期来自数据库记录，和 `doc/corpus-manifest.json` 的原始清单存在差异。
3. 评测集只有 15 题，不能证明系统在本科生、校区差异、历史版本、冲突条款和更多无答案问题上的稳定性。
4. 本轮使用外部 DeepSeek 服务，学校规则内容会发送到该服务。正式部署前需要确认数据合规、网络稳定性、费用和服务协议。

## 复现方式

服务已使用 `deepseek` profile 启动后，可打开 `http://localhost:8080` 进行人工测试。配置检查：

```powershell
Invoke-RestMethod http://localhost:8080/api/config | ConvertTo-Json -Depth 6
```

启动配置：

```powershell
$env:RAG_CHAT_API_KEY = '你的 DeepSeek API Key'
& .\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=deepseek'
```

本轮的检索、分块和端到端问答均已执行；DeepSeek 端到端问答通过正在运行的本地服务完成，没有读取或保存 API Key。
